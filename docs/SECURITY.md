# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in Sauti Labs' infrastructure,
scripts, or data pipelines, please report it privately rather than
opening a public GitHub issue.

**Do not disclose the vulnerability publicly until it has been addressed.**

To report a vulnerability, email **benardabuto081@gmail.com** with:

- A description of the vulnerability
- Steps to reproduce it, if applicable
- The potential impact

We will acknowledge your report and work to address confirmed
vulnerabilities as quickly as possible.

## Scope

This policy covers the Sauti Labs infrastructure and code layer
(`frameworks/`, `scripts/`, `.github/`), including our data validation
and licensing tooling.

This policy does NOT cover the content of third-party datasets stored
under `languages/` - concerns about the content or licensing of
specific third-party data should be raised as a normal GitHub issue,
since they are not security vulnerabilities in the traditional sense.

## Our Commitment

Per the AI CTO Constitution, uncertainty and mistakes are never hidden.
If a security issue is confirmed, we will document it honestly (see
`docs/Enhancements.md` for our existing pattern of tracking known
issues transparently) once it has been resolved.
